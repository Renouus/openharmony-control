## 关键根因修复：server.ts 初始化顺序（自动化在运行服务器上从未工作）

端到端验证时发现：针对运行中的后端 (3443) 创建自动化+触发后，规则不执行、无日志。
**根因**：`server.ts` 在模块加载时调用 `buildApp(registry)`（行12），而 `initDatabase()` 在 `main()` 内（行16）才调用。buildApp 内部 try 块调用 `getDb()` 时数据库未初始化 → 抛错 → catch 降级为 noop 运行时 → **所有自动化规则在真实服务器上从不触发**（测试通过是因为测试先 initDatabase 再 buildApp）。

**修复**：将 `buildApp(registry)` 移入 `main()`，在 `initDatabase` 之后调用；catch 改用 `console.error`（app 不再在模块作用域）。

### 端到端验证结果（针对运行中的服务器）
- 修复前：解锁 door-front → light-entry 不变（power 保持 false），无执行日志 ❌
- 修复后：解锁 door-front → light-entry 自动亮（power false→true），执行日志 success ✅
- WebSocket 验证：触发自动化后，UI 通道收到 `automation_run`（Toast）+ `DeviceStateUpdated`（设备卡片刷新）✅

### 结论
自动化在运行服务器上现已完整打通：命令→device_state_changed事件→评估→动作执行→WebSocket广播。App 只要 WebSocket 连着，触发时就会弹 Toast + 刷新设备卡片。

注意：tsx watch 每次重载会断开 WebSocket，App 若未自动重连需重启 App。

## 自动化列表项触发后消失 bug 修复

### 根因
竞态条件：时间触发自动化执行后，后端发送多条 `DeviceStateUpdated` WebSocket 事件 → 每条触发 `sync_completed` → `refreshAll()`（fire-and-forget，不 await）→ `listAutomations()` 后台 fire-and-forget `refreshAutomations()` → `automationDao.replaceAll()` 做 `DELETE FROM automations` + 逐条 INSERT（**无事务**）→ DELETE 后表短暂为空 → 下一条事件触发的 `refreshAll` 读到空/部分表 → store 被更新为空/部分列表 → UI 列表项消失。

### 三层修复
1. **`AutomationDao.replaceAll()` 加事务**：`beginTransaction` → DELETE + INSERT → `commit`/`rollBack`，消除空表窗口
2. **`refreshAutomations()` 改用 upsert**：新增 `AutomationDao.upsertAll()`（事务内逐条 insertOrUpdate，不 DELETE），后台刷新不再清空表
3. **去重保护**：`SmartHomeRepository` 加 `pendingAutomationRefresh` promise guard，并发 `refreshAutomations()` 调用复用同一个 promise
4. **修 version 硬编码**：`toAutomationSyncItem` 原用 `version: Date.now()`（远超后端真实 version，导致增量同步永不更新该自动化），改为 `version: 0`；`doRefreshAutomations` 中保留本地已有 version

### 改动文件
- `apps/openharmony-control/entry/src/main/ets/services/db/AutomationDao.ets`
- `apps/openharmony-control/entry/src/main/ets/services/smart-home-repository.ets`

## 三个缺陷修复（异常吞没 + 操作反馈 + 全量同步）

### 缺陷 2：Index.ets aboutToAppear 异常静默吞没
- **根因**：`isLoading = false` 嵌在 `syncProviderDevices().finally(() => refreshAll().finally(...))` 链中，与 try/catch 脱节。`await refreshAll` 抛异常时 catch 静默吞没，isLoading 可能永远不复位。
- **修复**：改为 `try { await refreshAll } catch { console.error } finally { isLoading = false }`，后台 syncProviderDevices 独立 fire-and-forget（sync_completed @Watch 驱动后续刷新）。
- **文件**：`apps/openharmony-control/entry/src/main/ets/pages/Index.ets`

### 缺陷 3：空调/门锁操作失败无用户反馈
- **根因**：`.then(() => {}).catch(() => {})` 完全静默。两个视图已有 `@State feedback` 字段和渲染 banner 但从未赋值。viewmodel 内部 catch 将错误转为 feedback 字符串存入 `this.home.feedback`，但视图未读取。
- **修复**：`.then(() => { this.feedback = this.home.feedback })`（读取控制器回写的 feedback）；`.catch((e) => { this.feedback = '操作失败提示'; console.error(...) })`（refresh 阶段异常兜底）。
- **文件**：`ClimateControlView.ets`（3 处：adjustTarget/togglePower/selectMode）、`LockControlView.ets`（2 处：toggleLock 解锁/锁定）

### 缺陷 4：listDevices 强制全量同步
- **根因**：`listDevices()` 每次调用 `performBackgroundSync(true)`（forceFullSync=true），导致 `createDevice → listDevices → 全量同步` 链中每次操作都全量拉取。
- **修复**：本地有数据时改用 `performBackgroundSync(false)`（增量同步，只拉取 lastVersion 后的变更）；新增 30 秒节流（`lastDeviceSyncAt` + `DEVICE_SYNC_THROTTLE_MS`）防止链式调用引发重复同步；同步失败重置时间戳允许重试。
- **文件**：`apps/openharmony-control/entry/src/main/ets/services/smart-home-repository.ets`
